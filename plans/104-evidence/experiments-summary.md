# Plan 104 experiment summary

On SQL Server 17.0.1145.4 Standard Developer, table variables emitted bare `#8hex` STATISTICS IO names while explicit `#ABCDEF12` and `#p104_temp` temp tables emitted their user names with internal suffixes. Same-session catalog lookups matched those suffixed explicit-temp names, and actual plans identified objects as `[@v]` versus `[#name]`. `TempTableKey.Normalize` removes the explicit-temp suffix, leaving `#ABCDEF12`, which the current shape classifier can mistake for a table variable. Raw suffix preservation is a promising signal on this build, but one version does not prove it universal; plan-to-counter association is not present in the current parser. No product code changed.

The first bounded matrix passed (7 cases, 3 repetitions/case, ≤1000 rows/object, localhost/tempdb only). During summary refresh the runner accidentally executed a second full matrix, so 6 total repetitions/case occurred across two retained runs. The runner now has mandatory explicit modes and no default execution. Full evidence and this deviation are in [experiments-report.md](experiments-report.md); initial stdout, plan details and hashes are in `experiments/`.
