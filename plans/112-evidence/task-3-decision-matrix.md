### Rejected and low-value alternatives

- **Always-roll-back DML under a read-only tier:** reject. The statement still executes and performs write activity; rollback does not eliminate all side effects or unknown outcomes.
- **Treat `SET STATISTICS XML` as an estimated plan:** reject. The inspected engine documentation says it executes the statement to produce runtime XML.
- **Infer per-index maintenance cost from Query Store aggregate metrics or `sys.dm_db_index_usage_stats.user_updates`:** reject. Aggregate query statistics do not assign cost to each index; usage counters count operations and have reset/availability limits.
- **Declare a redundant index from a matching leading key or emit DROP DDL:** reject. Constraint role, uniqueness, ordering, included columns, filters, partitioning, compression, other workload paths and incomplete metadata can change the conclusion.
- **Strip numbered parameter suffixes and promise canonical query-family identity:** reject as a contract. Family grouping may be a heuristic only, retaining exact members and requiring source/query-shape confirmation.
- **Broaden capture/output limits or add an index inventory endpoint from this one case:** low value now. No sample establishes repeat demand or response-budget need; Plan 063 already owns bounded hint overlap.
- **Treat the present absence of a live test as proof of zero demand or zero cost:** reject. Those are unavailable measurements, not zero.

## Reproducible synthetic workload specification (future proposal; not run)

This specification makes later review repeatable. It is not executable acceptance evidence and grants no database access.

1. **Fixture identity and data.** Use a private database named `Plan112Synthetic_<run-id>` created from a checked-in, content-hashed fixture script after separate authorization. Use deterministic seed `112`, fixed integer keys `1..100000`, and fixed UTC timestamps generated from the key (no wall-clock defaults or random functions). Record SQL Server product/version/compatibility level, collation, database options, fixture hash, and database snapshot/backup identity. Keep the fixture isolated from production data and credentials.
2. **Schema variants.** Create a clustered primary key on `dbo.WorkItem(Id)` in both variants. Variant A also has the observed-shape single-key nonclustered index on `Id`; Variant B omits only that nonclustered index. Capture the full catalog definition and object IDs for both. A reviewer must approve the schema and variant comparison before any future DDL; the document itself performs none.
3. **Deterministic operation sets.** For cardinalities `10`, `100`, `1000`, and `5000`, generate zero-based positions `i = 0..n-1` and keys `1 + ((112 * 7919 + i * 4729) mod 100000)`. The stride 4729 is coprime with 100000, so each set has unique keys. Sort each set ascending; compute its SHA-256 over the UTF-8 comma-joined decimal keys with no spaces or trailing comma. Each matched statement uses one `int` parameter per key: `DELETE FROM dbo.WorkItem WHERE Id IN (@p1, ..., @pn)`. Each clean reset starts with all 100000 keys, so expected affected rows equal `n`. Restore each variant from its own clean snapshot before every repetition. Use five paired repetitions per cardinality in this order: A/B, B/A, A/B, B/A, A/B; record every operation separately. A TVP comparison, if later selected, uses the same ordered keys and records unexpanded SQL, parameter-set identity, and cardinality as a condition.
4. **Controls and observations.** Record the exact SQL and parameter values/shape, plan XML, result/affected-row count, elapsed time, CPU, logical reads, waits, transaction log bytes if available, lock waits, errors/timeouts, and before/after index usage snapshots with capture interval and reset metadata. Preserve each repetition and variant identity. Record unavailable or permission-denied fields explicitly. Do not convert aggregate measurements into per-index cost attribution. Do not infer that the observed faster/slower variant proves a general index recommendation.
5. **Expected correctness.** Every operation must affect exactly its deterministic key-set cardinality; a mismatch invalidates that pair. A fresh snapshot reset must restore the original 100000 rows and variant schema before each repetition. The workload expects equivalent row results, not a predetermined performance winner. Any trigger, external endpoint, unexpected DDL, changed schema hash, incomplete catalog visibility, or reset failure invalidates the run and stops further work.
6. **Evidence boundary.** Estimated-plan capture and actual-write measurement are separate experiments with separate permissions and records. Estimated evidence is not execution or runtime acceptance. Actual-write evidence exists only for the named isolated target and recorded workload; it cannot be generalized to production or treated as a safe rollback test.
