# Plan 115: Select relevant query result sets

> **Status:** accepted research follow-up from Plan 109; TODO. This file is an implementation handoff, not authorization to implement, merge, push, use a live database, or run paid-agent trials.

## Evidence and goal

Plan 109's deterministic projection retained the success status, target database, query hash, source result-set count, original ordinals and both assertion result sets in 646 UTF-8 bytes. The existing query response for the same fixture used 11,469 bytes because it also included an unrelated 96-row first set and envelope detail. This is a 10,823-byte (94.4%) reduction for that assertion check only. See [decision evidence](109-evidence/task-3-decision.md) and [reproduction record](109-evidence/task-3-reproduction.md).

Allow a caller to retrieve selected result sets from the already executed query response. This is an output-selection feature; it does not promise less SQL execution or row materialization.

## Contract

1. Add exactly one optional query request field to both fixed and request `sqlharness_query` tools: `resultSetOrdinals`, nullable `integer[]`, default null, item minimum 0, maximum 64 items. Null means the existing behavior and JSON shape (current prefix under existing output bounds); an explicit empty array selects no result sets. Sort accepted values into source order. Reject duplicate, negative and out-of-range ordinals and arrays longer than 64 with a clear input error. Add it to the fixed/request schemas, descriptions, and unknown-key allowlists. Do not add aliases.
2. The MCP v3 envelope remains unchanged (`schemaVersion`, `status`, `result`; optional `error`, `truncation`, `operationRef`). For an opted-in successful query, `result` is the existing `AgentCompactQuery` fields (`database: string`, `statementClassification: string`, `resultSets: array`, `omittedResultSetCount: integer`, optional `messages: string[]`, optional `recordsAffected: integer`, `durationMilliseconds: integer`, optional `warnings: string[]`) plus exactly `sourceResultSetCount: integer`, `selectedResultSetOrdinals: integer[]`, and `queryHash: string`. `queryHash` is uppercase hexadecimal SHA-256 of the exact resolved SQL UTF-8 bytes (inline SQL or file contents, with no normalization). The envelope `status` distinguishes success from errors; on errors the existing envelope error path remains in force.
3. Each emitted `resultSets` item has the existing `ordinal: integer`, `columns: array`, `rows: array`, `rowCount: integer`, and optional `omittedRowCount: integer`, `omittedColumnCount: integer`, `clippedCells: array`, `projectionOmittedRowCount: integer`, and `sourceOmittedRowCount: integer`. Each column has `name: string`, `valueType: string`, and `allowNull: boolean`; rows retain the existing arrays of JSON scalar/null values. Set ordinals are original zero-based source positions.
4. `omittedResultSetCount` retains its existing field and means source sets not present in `resultSets` due to explicit selection or response budgeting. `sourceResultSetCount` is the full source count; `selectedResultSetOrdinals` lists requested ordinals after source-order normalization, including any selected set omitted by the byte budget. Existing row/column/cell omission fields continue to describe partial content within emitted sets. Do not introduce a separate projection name or response schema version.
5. The selected response preserves each set's original schema, rows, row count and existing row/column/cell clipping metadata. It preserves resolved target database, statement classification, query hash, messages, warnings, records affected and duration.
6. Bound selector length at 64 items and enforce ordinal validity against the source result-set count after execution. A selection that skips an earlier set is represented by each original `ordinal` plus `sourceResultSetCount` and `selectedResultSetOrdinals`; it is not coerced into a prefix.
7. Distinguish valid success with zero result sets, an explicit empty selection, a structured error, and missing/incomplete result evidence. A missing result collection must never become a successful empty check. Selection must not make execution errors disappear.
8. Omitted selector behavior, query execution, database scope, row/cell limits and safety checks remain unchanged. The selector only limits response projection after execution.
9. Keep fixed/request MCP schemas, unknown-key allowlists, served descriptions, capabilities and `docs/mcp/tools.md` in agreement. Do not put interface contracts only in README or user-facing skills.
10. Preserve bounded output and truthful clipping/omission under the minimum result budget, including long escaped/multibyte values. A selected set that cannot fit must be reported as omitted or clipped with the existing metadata; do not return a partial set as complete.

## Scope and implementation checks

Inspect `AgentCompactQuery` and query projection in `AgentOutputProjection.cs`, the query operation/mapper, `McpToolCatalog.cs`, `McpRequestToolHandlers.cs`, schemas and capabilities. Add focused offline MCP tests for omitted selector compatibility, first/middle/last and non-prefix selections, empty selection, invalid/duplicate/out-of-range input, error and missing-output boundaries, and output-budget clipping. Compare full-task UTF-8 retrieval bytes with the frozen Plan 109 fixture, retaining source ordinals. Assert that query execution still occurs once and receives the original SQL and parameters.

UTF-8 bytes and byte/4 estimates are not tokenizer or model-savings measurements. No live database or live-agent acceptance is authorized or required by this plan.
