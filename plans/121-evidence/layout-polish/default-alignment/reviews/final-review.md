## Findings for the single combined fix wave

1. **P3 — New Profiles explanations inherit non-wrapping table cells.** `src/SqlHarness.Dashboard/ui/src/pages/ProfilesPage.tsx:72`. Both new `ExplainedValue` instances in the Mutations table sit in default `TableCell` elements whose `whitespace-nowrap` is inherited by the explanatory paragraphs. On a 390px viewport with an ordinary `operator` / `sameAsReader` profile, I independently measured a 326px table viewport containing 488px of content. The operator must scroll horizontally to finish short policy/writer explanations; the supplied `profiles-mobile-app.png` also shows the cut-off prose. This weakens the readable mobile explanation objective even though document overflow is zero. **Fix:** allow wrapping in these two prose cells (`whitespace-normal` plus appropriate word wrapping), retaining standard Table/Card appearance and raw unknown-value fallback. Check operator, YOLO and writer descriptions at 390px. This is a newly introduced presentation regression.

2. **P3 — Long profile names still overflow the mobile document.** `src/SqlHarness.Dashboard/ui/src/pages/ProfilesPage.tsx:70`. The detail heading is an unconstrained flex child with no wrapping rule for unbroken identifiers. Using `reporting_production_read_only_customer_invoices_north_europe`, I independently measured a 638.66px heading and a 655px document at a 390px viewport. This is an ordinary profile identifier, and the plan explicitly requires long profile identifiers not to overflow the document. Existing screenshots exercise short names only. **Fix:** permit this heading to shrink and break long identifiers within its available width, preserving the full readable identifier and normal shadcn typography; check desktop and mobile with a long identifier. This markup predates the follow-up: classify this as an explicit acceptance gap, not an introduced regression or an invitation to a wider Profiles redesign.

3. **P3 — Empty Add note stretches across Session.** `src/SqlHarness.Dashboard/ui/src/pages/SessionPage.tsx:92` (new flex parent at line 55). `SessionNoteCard` returns a direct Button when note/draft are null, so the new `flex flex-col` page stretches it to full width. The task-2 review and current Session screenshot confirm the change. **Fix:** wrap the invocation in an ordinary block container or constrain only the empty button. Preserve full-width saved-note/editor states. Check empty, editing and saved/re-edit states. This carries forward the already identified task-2 finding.
