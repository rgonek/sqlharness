# MCP artifacts

## Benchmark artifact storage

`measure` (including parameter sets) and `compare` (including matrices) check the benchmark artifact directory after input validation and before opening a database session. The check creates a unique probe directory, writes a nonsensitive marker, renames the directory, and removes the probe. It uses the same storage root as artifact publication and leaves existing artifacts untouched.

The process account must be able to create directories, write files, rename directories, and delete its files and directories under the artifact root (by default `~/.sqlharness/compare`). On Windows, an MCP client may launch a restricted process whose effective permissions differ from those of an interactive terminal. Check the actual MCP process identity and token before changing access rules; keep any access grant limited to the required artifact directory.

A failed probe returns `local_storage_failed`, exit code `6`, phase `artifact-preflight`, a redacted storage location, and a permissions hint. SQLHarness never changes ACLs or elevates the process. A successful check does not guarantee a later write will succeed: permissions, disk space, or other filesystem conditions may change during the benchmark. Publication failures still retain completed matrix cells and use the existing staging cleanup behavior.

`SQLHARNESS_HOME` changes the whole SQLHarness home, including configuration and profiles, not just the artifact directory. Changing it requires deliberate operator configuration. Read-only `query` does not run this benchmark storage check.

## Artifacts

Benchmark and snapshot artifacts are read through the shared controlled reader with a scope-bound opaque id: a call can only address artifacts of its own scope, never arbitrary paths or other profiles' artifacts. The safe benchmark sections are `summary`, `metrics`, `operators`, `statements`, `statement-summary`, `matrix-cells`, and `plan`. Compact measure and compare responses include `statementEvidence`, grouped by variant, parameter set, and matrix cell. Its `counterAttribution` values describe coverage of collected statement counters only; `complete` does not establish complete query cost. `partialStatementCount`, `unavailableStatementCount`, and `limitations` stay scoped to that case. The top-level `artifactId`, or each affected matrix case's `artifactId`, is executable: pass that reference to `sqlharness_artifact` with `section: "statements"` to retrieve exact `(variant, parameterSet, matrixCell, statementOrdinal, repetition)` identities and any hidden UDF/TVF limitations. An omitted statement or case count signals bounded projection and can never imply complete coverage. Legacy or PostgreSQL statement evidence remains `unavailable`; missing counters are not zero.

`statements` reports each variant's statement ordinal, SQL hash, CPU and elapsed time from SQL Server `QueryTimeStats`, degree of parallelism, and up to ten operators ranked by actual rows and executions. Its bounded `objects` list carries per-statement logical reads, LOB logical reads, and Showplan `ActualScans` separately; `objectIoAvailability` is `available`, `partial`, or `unavailable`, and missing counters remain null. Run-level `statisticsIoScanCountRuns` carries SQL Server `STATISTICS IO ScanCount` by table, separate from those per-statement Showplan counters. `planDiagnostics` keeps the source plan identity and its degree of parallelism, requested/granted/max-used memory, compile time, and compile CPU. `planDocumentOrdinal` and `planQueryOrdinal` identify each source `QueryPlan`; the latter is zero-based within its saved plan document, so separate query plans under one statement or at batch scope remain distinct. `metrics` distributions keep those ordinals in their identity and report `partial` when an older artifact lacks ordinals needed to disambiguate repeated sources. Old records without a query-plan ordinal remain attributable when unique within each repetition; ambiguous records are omitted and counted. Corrupt, oversized, or unreadable advertised `statements.json` evidence makes a metrics read fail safely instead of looking like an empty capture. Valid older artifacts with no diagnostic fields remain `unavailable`; missing diagnostics are not zero. These reads are optional follow-up evidence for questions about memory, compile cost, or statement IO; ordinary optimization does not require fetching them. `metrics` provides bounded run distributions for captured diagnostics, with source and availability fields plus omission counts. A partial metric response is incomplete by design: use `statements` and its continuation for exact source records. `statements` omits statement text and carries an omitted-statement count when the bounded projection is truncated. PostgreSQL plans do not provide these SQL Server statement diagnostics, so their availability remains `unavailable`; missing diagnostics are not zero. Compare cell inventories carry each cell index, its artifact id and additive `setName`; matrix cells also carry displayed `parameterValue`, with JSON null for a typed NULL. Older artifacts with only `parameterValue` remain readable. If an oversized compare result continues onto another page, `sqlharness_artifact` with `section: "matrix-cells"` returns the remaining cell references in the same schema, then each returned cell id can be read through `summary`, `metrics`, `operators`, or `statements`. Every page repeats the same scope-owner check, and wire budgets apply to each response. The `plan` section reads saved distilled plan JSON only, when the artifact contains it; it does not read or regenerate raw XML. It accepts `variant` (`baseline`, `candidate`, or `query` for measure), zero-based `statement` (default `0`), `parameterSet` for measure-set artifacts, measured `repetition`, and `includeText` (default `false`). For measure and measure-set artifacts, an omitted or empty `variant` selects `query`; compare requires an explicit `baseline` or `candidate`. Other nonempty values, including values with different casing or whitespace, are rejected with the accepted variants for that artifact kind. Without `repetition`, it selects and labels the last measured repetition. Available repetitions list all measured runs, including runs without a saved plan; selecting one without plan evidence returns an explicit error instead of falling back. The response gives the available measured repetitions and `planShapeStable`; stability is `true` or `false` when comparable plan evidence exists. With fewer than two measured repetitions, stability is `null` and `evidenceGaps` is empty because there is not enough evidence to compare. For a multi-repetition comparison with missing or incomplete saved plan evidence, stability is also `null` and `evidenceGaps` describes the gap. It compares operator/object/index/predicate shape, not costs, row counts, or timing. Where exposed, `estimatedRows` is the optimizer estimate for an operator, `actualRows` is the observed runtime row count, and `executions` is the runtime execution count; read them together when comparing estimate accuracy and repeated operator work. These fields are plan evidence, not elapsed-time or equivalence verdicts. Nodes are flattened in deterministic preorder with stable paths and paged by the zero-based `cursor`, so following continuation reconstructs the saved hierarchy. Each response is trimmed to its byte budget; returned node counts vary with content and budget, continuation advances by the number of nodes returned, and clipping metadata counts returned clipped fields once. If the next node cannot fit, the response reports that no node fits and does not advance the cursor. `operators` is also paged, but its saved noteworthy-operator source is capped and does not promise full-plan coverage. Per-table read details normalize SQL Server session-suffixed temp-table names (`[schema].[#name<underscores><12 hex>]` to `[schema].[#name]`, or `#name<underscores><12 hex>` to `#name`) before aggregation across repetitions; other table names are unchanged. There are no MCP resources in v1; the single artifact tool is the only detail surface. Raw plans and snapshot cells are never exposed.

`sqlharness_artifact` accepts `maxResultBytes` (4096..1048576, default 65536, capped by the server's process limit) and `pageSize` for `matrix-cells`, `operators`, `statements`, `statement-summary`, and `plan`. `pageSize` requests a bounded source window of 1..512 items; when omitted, the defaults are 32 matrix cells, 32 operators, 128 statements, 128 statement-summary records, and 128 plan nodes. The byte budget and source window are separate limits: projection can return fewer complete records than requested to fit the response, and continuation advances from the last record actually returned. Repeat the same selectors, budget, and page size while following continuation. A larger window can reduce the calls needed to read a complete saved artifact, while increasing the bytes returned per call; neither UTF-8 response bytes nor a byte reduction directly measures model-token savings.

Every live publish stamps the frozen scope owner into versioned metadata written by the trusted Core writer (the MCP adapter and the CLI never stamp it themselves): the benchmark `ArtifactManifest` and the `SnapshotDocument` each carry a strictly additive, nullable `owner` field (`profile`, `vars`, `engine`, `server`, `database`, camelCase in JSON). Reports (`report.json`, `runs.jsonl`) are unchanged; the bounded `statements.json` artifact section contains hashes and plan metrics but no SQL text. Scope vars and fixed parameter values are never copied into reports. Matrix parameter values appear in the explicitly scoped matrix-cells inventory so each case remains identifiable. The owner check is namespacing, not access control: it keeps each MCP scope to its own artifacts and snapshots, while any local process running as the operator (a CLI agent with a shell included) reads the files directly. The check is opt-in per call inside Core, before any report projection: MCP always passes the frozen scope owner, the CLI passes none and keeps working by name. A scope mismatch is refused with a constant content-free message (`"The artifact is not available in the current scope."`, exit 2 `Safety`; snapshots: `"The snapshot is not available in the current scope."`, exit 2) with `isError=true` and no projection, so no operator names, index names, or cell values leak. Unavailable storage stays exit 6 `LocalStorage`. Snapshot capture additionally refuses before connecting when the existing name belongs to another scope (no self-grant), and scoped diff refuses a foreign baseline before connecting; a scoped capture over the scope's own existing name without force still runs the query and then reports `LocalStorage` (no overwrite), exactly like the CLI.

`compare --matrix` cells inherit the calling scope's owner (same profile/vars/engine/server/database; the matrix value is an execution parameter, not scope identity). `measure --param-set` carries one scope owner for the whole `measure-set` artifact; individual sets (name, value hash, types) are data inside, not separate owners. Legacy compatibility: v1 artifacts and snapshots without an owner stay byte-identical on write (the key is omitted, not nulled) and remain readable by the CLI by name, but MCP refuses them — fail closed, with no automatic migration and no way for MCP to grant itself access by name. The local process-privileged writer is outside the integrity boundary: the manifest is scope metadata for one trusted host, not a cryptographic proof against manual local edits.

### Compact statement discovery

`statement-summary` is an opt-in discovery view for per-statement CPU and elapsed values. It returns only (`variant`, `parameterSet`, `matrixCell`, `statementOrdinal`, `statementHash`, `cpuTimeMilliseconds`, `elapsedTimeMilliseconds`) plus artifact identifiers, `omittedStatements`, and optional `continuation`. A null `parameterSet` follows the existing null omission behavior; missing CPU or elapsed values stay JSON null. The view has no repetition identity and cannot select or replace saved plan evidence. Use `statements` when you need exact repetition identity, operators, plan diagnostics, IO, or hidden-work evidence; existing `statements` output retains its full shape and `topOperators`.

`sqlharness_artifact` pages both sections with the existing 1..512 `pageSize` bound and 128-record default. Complete retrieval comparisons should count UTF-8 bytes from each full bounded MCP response and report call counts separately; these byte counts do not measure tokenizer or model savings.
