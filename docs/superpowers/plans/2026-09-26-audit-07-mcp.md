# MCP adapter Implementation Plan

**Status (2026-10-08):** DONE — 975da6a..c962646 (2026-09-28), dokumentacja `docs/mcp.md`; dalsze poprawki w `plans/001`–`012`. Checkboxy poniżej nie były odhaczane w trakcie wykonania.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Udostępnić lokalny serwer MCP SQLHarness po zakończeniu planów audytu 01–06, ze wspólnym Core, bezpiecznym scope i ograniczonym kosztem odpowiedzi.

**Architecture:** `sqlharness mcp serve` uruchamia stdio host z biblioteki SqlHarness.Mcp. Adapter mapuje typowane argumenty do istniejących operacji Core i wspólnej projekcji agentowej; nie uruchamia CLI ani SQL przez shell.

**Tech Stack:** .NET 8, oficjalny ModelContextProtocol C# SDK (stabilna zgodna wersja przypięta w T1), System.Text.Json, xUnit. Brak HTTP/SSE w v1.

**Spec:** [MCP adapter design](../specs/2026-09-26-mcp-adapter-design.md), [kolejność całego programu](2026-09-26-audit-roadmap.md).

## Global Constraints

- **Realizować po 01–06.** Projektowe rezultaty 06/T4–T5 nie są wdrożonymi funkcjami. Późniejszy [plan 08](2026-09-26-audit-08-windows-approval-tray.md) dodaje Windows tray i zgody; nie rozszerza zakresu pierwszej wersji MCP w tym planie.
- Jeden proces ma jeden zamknięty profil i vars ustalone przy starcie; tool nie zmienia celu ani credentials.
- Brak trwałych mutacji i unsafe-direct w MCP v1. Sesyjne temp tylko zgodnie z Core.
- Jedna aktywna operacja DB; druga otrzymuje BUSY. Scope nie jest sesją DB i nie dzieli temp między tools/call.
- 11 narzędzi maksymalnie, katalog tools/list ≤32 KiB; CallToolResult domyślnie ≤16 KiB łącznie z dwiema reprezentacjami.
- Param-set wyłącznie jako istniejące pliki .sqljson; file input tylko w jawnych roots operatora. Bez publikacji raw plans, SQL tekstów i snapshot cells przez artifact.
- Stdout tylko protokół; stderr bez sekretów. Żadnej osobnej walidacji SQL w MCP.
- Nowe wersje SDK nie uzasadniają niejawnej zmiany frameworka ani standardów repo.

## Definition of done

Serwer uruchamia się z istniejącej binarki, klient MCP odkrywa i wykonuje zdefiniowane narzędzia, a transport nie osłabia reguł Core. Dowody obejmują realny stdio proces, kontrolę celu, redakcję, budżet schemas/wyników, cancellation oraz publish smoke. Zmiany dokumentacyjne bez implementacji nie spełniają tego kryterium.
